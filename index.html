I build software for businesses, full-time — apps, stores, dashboards and the servers behind them. Most of what you see here is live and in daily use.

I didn’t come from a software company — I learned by building for real businesses. For Pakiza Mart, a grocery in Gujranwala, I built the customer app, the dashboard the staff run the shop from, and the server between them. I secured it, got it through Google Play’s review and put it into production. The herbal store started on Shopify; today it runs on a platform I wrote myself.

That’s still how I work: understand what the business actually needs, build the whole thing end to end, and treat it like it’s handling real money — because it is. Now I build the same for other businesses through KONO — from a surgeon’s bilingual website to a knife store selling worldwide.

    How I build

    Rules I learned by shipping.

    (04)
    01 — Pakiza Mart API

    Never trust the price the app sends.

    Every order total is recalculated on the server from real database prices. A tampered app can’t buy a Rs 3,000 basket for Rs 30.

    01
    02 — Veloura

    Make the wrong thing impossible.

    Instead of a rule that says “don’t edit orders directly”, the ability simply doesn’t exist in the code. Conventions get forgotten. Types don’t.

    02
    03 — migration-engine

    A loud failure beats a quiet success.

    Anything unfinished throws an error instead of pretending it worked. Silent data loss is the only unforgivable bug.

    03
    04 — Every deploy

    Always ship with an undo button.

    Before anything goes live, the database is backed up and the running version is saved. If the smoke test fails, one command puts it all back.
